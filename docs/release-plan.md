# 本番リリース計画

今の公開環境は「お試し環境」（ダミーのデータで機能を試してもらう形）です。

## 1. 目的と範囲

- **目的**：お試し環境（ダミーのデータ・無料の枠）から、本物の利用者が安心して記録を預けられる本番に移る
- **範囲**：公開先の設定・データ・資料・最小限のコードの直し。新しい機能は入れない
- **お試し環境の制約として割り切っていること**：下の表の「今（お試し環境）」の欄。要件の未完了ではなく、無料の枠とお試しのための割り切りで、本番では「本番では」の欄に変える

## 2. 変える項目

優先度：**必須**＝本番を始める前に必ず変える／**推奨**＝始める前に変えるのがよい／**あとで**＝利用者が増えてきたら変える

### 公開先と外部サービス

| # | 項目 | 今（お試し環境） | 本番では | 変えること | 優先度 |
|---|---|---|---|---|---|
| 1 | アプリのサーバー | Render の無料のプラン。15分使われないと止まり、UptimeRobot で5分おきに開いて起こしている | 止まらない有料のプラン | Render のプランを上げる。UptimeRobot は「止まったら知らせる」役だけにする。起こすための GitHub Actions（keep-alive）は止める | 必須 |
| 2 | データベース | Aiven の無料のプラン（1GB、使われないと止められる、SLA なし） | 止められない有料のプラン | Aiven のプランを上げる（データはそのまま移せる）。バックアップの保持の期間を確かめる | 必須 |
| 3 | ドメイン | `fishing-log-hasx.onrender.com`（Render の住所） | 自分のドメイン（例：`fishinglog.jp`） | ドメインを取り、Render に設定する（HTTPS は Render が用意する）。`APP_URL` を変える | 推奨 |
| 4 | メールの送り主 | 無料の Gmail（`fishinglog.dev@gmail.com`）。迷惑メールに入りやすい | 自分のドメインのアドレス（例：`no-reply@fishinglog.jp`） | Brevo でドメインを認証し（DKIM・DMARC の設定）、`MAIL_FROM_ADDRESS` を変える | 必須 |
| 5 | 写真の置き場所 | Cloudflare R2 の無料の枠（10GB） | そのまま | 使用量が無料の枠を超えそうになったら有料にする | あとで |
| 6 | 起動時の処理 | 起動のたびにマイグレーションとお試しデータの準備（ロックで重ならないように） | デプロイのときに1回だけマイグレーション | Render の Pre-Deploy Command（有料のプランで使える）に `php artisan migrate --force` を移し、`docker/start.sh` から外す | 推奨 |

## 3. 移る日の手順

移り方は2つあります。どちらにするかは、移ることを決めたときに決めます。

| 移り方 | 中身 | よいところ・気になるところ |
|---|---|---|
| A. 本番の環境を別に作る | 今のお試し環境は残し、Render・Aiven・R2 をもう一組作って本番にする | 見せる用と使う用が混ざらない。外部サービスの設定が2組になる |
| B. 今の環境を本番に切りかえる | 同じ環境のまま、ダミーを消して本番にする | 作業が少ない。お試し環境はなくなる |

### B の場合の手順（例）

1. **前もって**：表の「必須」のコードの直し（8・9・17）を PR にしてマージしておく（お試しモードはまだ ON のまま）
2. **お知らせ**：README とお試し環境に、切りかえの日時と、その間は使えないことを書く
3. **今の状態を残す**：GitHub の Actions → バックアップ → Run workflow で、移る直前のバックアップを取る
4. **プランを上げる**：Render・Aiven を有料のプランにする（1・2）
5. **設定を変える**：Render の環境変数で `DEMO_MODE=false`、`DEMO_RESEED_TOKEN` を消す、メールの送り主を変える（4）。ドメインを使うなら `APP_URL` も（3）
6. **ダミーを消す**：9 のコマンドを1回だけ動かす
7. **資料を変える**：README・利用規約・プライバシーポリシー・運用の手順書（18〜20）
8. **開発者の釣行を登録する**（10）
9. **確かめる**（下の「4. 移ったあとに確かめること」）

### うまくいかなかったときの戻し方

- 5 までの間なら、環境変数を元に戻して公開し直す
- 6 のあとなら、3 で取ったバックアップから [`docs/backup.md`](backup.md) の「本番に戻す手順」で戻す
- 戻したら、原因を Issue に残し、直してからもう一度移る

## 4. 移ったあとに確かめること

- [ ] 実在の港と湖が残っていて、ダミーの釣行・釣り人・お試し用アカウントが消えている
- [ ] 新しく会員登録し、確認のメール（12 を入れたとき）が届き、釣行を記録できる
- [ ] パスワード再設定のメールが、自分のドメインのアドレスから届き、迷惑メールのフォルダに入らない
- [ ] サンプルのイラストが付かない。起動し直しても、ダミーが入らない
- [ ] 毎日のバックアップが成功し、戻す試しの件数が本番と一致する
- [ ] GitHub Actions のテストがすべて成功する
- [ ] 15分以上あけて開いても、すぐ表示される（止まらない）
- [ ] 要件の対応表（[`docs/requirements.md`](requirements.md)）の FN-13・NF-07 を完了にし、版を上げる
