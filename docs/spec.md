## 案件定義書

案件定義書：釣果記録・釣り場情報共有アプリケーション

このアプリで何を作るのかをまとめたメインのシート。迷ったらまずここに戻る。

### ■ 1. プロジェクト基本概要

| 項目 | 定義内容 |
|---|---|
| システム名称 | 釣果記録・釣り場情報共有アプリケーション |
| 価値提案（一言で） | 次の休日にどこへ行って、どう釣れば釣れるのかを、自分と他の釣り人の記録から決めるためのアプリです。「釣ったあとに投稿するアプリ」ではなく「行く前に開くアプリ」にします。 |
| 目的・背景 | 釣り場ごとに「いつ・どんな条件で・どんな釣り方で・何が釣れたか」と、駐車場やトイレなどの現地の情報を貯めていきます。それによって、釣り人が「次はどこへ行くか」「そこでどう釣るか」を記録にもとづいて決められる状態をつくります。自分の記録は1回目の釣行から、その釣り場のカルテとして使えます。さらに他のユーザーが公開した記録と合わせれば、行ったことのない釣り場でも判断の材料を持てます。秘密のポイントは非公開にできることを前提にして、使うほど自分にも全体にも精度が貯まっていくサービスにします。 |
| 現状の課題 | 車で片道１〜２時間、半日以上と交通費をかけて行く釣行だからこそ、記録を根拠に行き先と釣り方を選んで、釣れる確率を上げたいと考えています。しかし実際は、月１〜３回の自分の釣行は写真フォルダと記憶に流れていくだけで、あとから取り出せません。行ったことのない釣り場になると、釣れる条件も釣り方も、駐車場やトイレがあるのかすら分かりません。その結果、前に坊主だった場所と気づかずにまた行ってしまったり、釣れたときの潮・天気・釣り方を覚えていないので同じ釣り方を再現できず、かけた時間とお金に見合う釣果を出せていません。これは自分だけの問題でなく、記録を持たない釣り人に共通して起きていることです。 |
| 対象ユーザー | 釣りをする人全般です。アカウント登録をすれば誰でも使えるWebサービスにします。開発者自身も利用者の1人として想定します。 |

### ■ 2. 主要機能要件一覧

| 機能No | 機能カテゴリー | 機能名 | 概要・要件詳細 |
|---|---|---|---|
| FN-01 | データ管理 | 釣り場・釣行・釣果CRUD機能 | 釣り場・釣行・釣果の3つを登録・編集・削除できます。釣り場には場所・都道府県・位置・現地の情報を、釣行には日時・時間帯・潮・天候・公開範囲を、釣果には魚種・サイズ・重量・釣り方・写真を持たせます。<br>釣り場は初回だけ登録し、2回目以降は一覧から選びます。他のユーザーが登録した釣り場も選べます。<br>魚種は自由に入力せず、主な20種の一覧から選びます（ないものは「その他」で入力）。「シーバス」と「スズキ」のように同じ魚を別の名前で登録すると、あとで集計するときに別の魚として数えられてしまうためです。<br>釣果が0件でも、釣行だけを「坊主」として記録できます。編集と削除できるのは本人のデータだけです。 |
| FN-02 | 分析・可視化 | シーズンヒートマップ | 月別×魚種別の釣果数を表にして、数が多いところほど濃い色で表示します。「この月にはこの魚が釣れる」が一目で分かるようにするためです。<br>釣り場カルテ（FN-09）と同じ記録を、集計の切り口を変えて見る機能です。記録が貯まるほど役に立つので、Phase 2 で作ります。 |
| FN-03 | 検索・抽出 | データフィルタリング（条件検索） | 釣り場・魚種・期間に加えて、潮（大潮・中潮など）・天候・時間帯（朝マズメ・日中・夕マズメ・夜・終日）・釣り方（エサかルアーか）を組み合わせて絞り込めます。<br>「大潮×朝マズメ×曇り×ルアー」のような検索で、「この条件ならこの釣り方で釣れる」を引き当てられるようにします。自分の記録と、他のユーザーが公開した記録を切り替えて検索できます。<br>時間帯は釣行日時から計算せず、釣行を登録するときにユーザーが選んだ値を使います。朝5時から夕方まで通すような釣行もあるため、日時だけでは時間帯を決められないからです（そういう釣行は「終日」で記録します）。 |
| FN-04 | データ連携 | CSVエクスポート | 自分が登録した釣行・釣果と、その検索結果をCSVファイルでダウンロードできます。<br>出力できるのは自分のデータだけです。他のユーザーの公開データは、公開範囲に関係なく出力の対象にしません。公開している情報をまとめて抜き取られないようにするためです。釣行一覧で他の人の公開記録を表示しているときは、CSVのボタンを出しません。 |
| FN-05 | 認証・アカウント | ユーザー認証／プロフィール管理 | 会員登録・ログイン・ログアウト・パスワード再設定・プロフィール編集・退会までを、Laravel Breeze（認証の標準機能セット）で用意します。<br>会員登録のときに、メインフィールド（よく行く都道府県）を必ず１つ選んでもらいます。あとでプロフィールから変えられます（FN-17）。あわせて利用規約とプライバシーポリシーへの同意を必須にします（NF-05）。<br>自分のデータを編集・削除できるのは本人だけです。他のユーザーのデータは、公開されているものを見ることだけができます。 |
| FN-06 | 分析・可視化 | サマリー指標ダッシュボード | 累計の釣果数・釣った魚種の数・釣行した日数・自分の最大サイズを表示します。<br>これらは記録が１件でも必ず数字が動く指標です。釣り場カルテが判断に使える量まで育つまでの間も画面が空にならないようにし、記録を続ける動機にします。 |
| FN-07 | 分析・可視化 | 釣果ハイライト表示 | 釣果を登録した直後に、「自分の最大サイズを更新」「初めて釣った魚」「この釣り場では初記録」などを判定して表示します。<br>記録１件ごとに手応えを返すことで、判断材料が貯まる前に記録をやめてしまうのを防ぎます。 |
| FN-08 | データ管理 | 写真Exif・気象／潮汐の自動補完 | 写真にExif（写真に埋め込まれた撮影日時と位置の情報）があれば、そこから日時と位置の候補を読み取ります。端末のGPSからも取得します。<br>位置は釣り場を初めて登録するときにだけ使い、最後は地図のピンでユーザーが確定します（自動では候補を出すだけにします）。候補の位置が登録済みの釣り場から数百ｍ以内なら、「この釣り場ですか？」と提案します。<br>この提案の対象は、「公開されている釣り場」と「自分が登録した釣り場」だけにします。他の人の非公開の釣り場を提案すると、その場所があることと正確な位置が分かってしまうためです。<br>写真のExifは、公開・非公開に関係なくアップロードした時点で必ず消してから保存します。あとで非公開から公開に切り替えても、写真から位置が漏れないようにするためです。正確な位置は釣り場（spots）のデータとしてだけ持ちます。<br>潮の名前（大潮・中潮など）は釣行日時から旧暦を計算して自動で決めます。天候は釣り場の位置と日時をもとに外部のAPI（天気のデータを提供してくれるサービス）から取得します。取得できないときは一覧から選んで手入力します。時間帯は自動判定せず、ユーザーが選びます。<br>写真は任意です。写真がない釣行も、日時・釣り場・魚種だけで登録できます。昔の釣行をあとから登録しやすくするためです。初回利用時には、過去の釣行をまとめて登録できるモードを用意します。 |
| FN-09 | 分析・可視化 | 釣り場カルテ | 釣り場ごとに、釣行の履歴・釣れたときの条件と釣り方・自分の最大サイズ・最後に行った日・現地の情報を１画面にまとめます。釣り場の「カルテ」のような画面です。<br>画面の上部に主役機能のFN-11（釣行判断ビュー）を置き、「今日の条件」の下に過去の実績を並べます。<br>実績は件数だけでなく、「その釣り場に行った回数」と「釣果があった回数」の両方を出します（例：5回行って3回釣れた）。坊主も含めた確率として見られるようにするためです。<br>釣り場は全ユーザー共通のデータとして持つので、名前の書き方の違いで集計が割れません。自分の実績は釣行１件目から、公開された他人の実績と合わせれば行ったことのない釣り場でも使えます。 |
| FN-10 | 分析・可視化 | 継続支援表示 | ヒートマップの空のマスに「あと何件で表示されるか」を出します。あわせて、今月の釣行回数・連続で記録している月数・前年同月との比較を表示します。<br>釣行3件目からは「気づきカード」（例：大潮のときに釣れているようです）を出します。何件の記録から言っているのかも一緒に表示します。<br>月１〜３回という頻度でも記録が途切れないようにし、釣り場カルテが判断材料になる量まで育つのを支える機能です。 |
| FN-11 | 分析・可視化 | 釣行判断ビュー（釣り場別の条件照合） | FN-16（釣行プランナー）で行き先を絞ったあとに開く、釣り場１つ分の判断画面です。<br>釣り場カルテを開くと、その釣り場の位置をもとに「今日（または選んだ先の日付）の潮・天気・時間帯」を表示します。その下に、過去にその場所で釣れたときの条件を並べて、条件が一致する釣行に印をつけます。<br>「今日ここに行くべきか」「行くならどう釣るべきか」に答えるのが目的です。釣果を記録したあとでなく、釣りに行く前に開く画面として設計します。<br>潮の名前は計算で出せるので先の日付でも表示でき、「次の大潮はいつか」も示せます。<br>他の釣果記録アプリが「釣ったあとに投稿する」道具であるのに対して、このアプリの特徴はFN-16とこのFN-11の2つに置きます。 |
| FN-12 | 共有・公開 | 釣行ログの公開範囲設定（3段階） | 釣行１件ごとに、公開範囲を次の3つから選べます。①全体公開、②釣り場だけ隠す、③非公開。初期値は非公開です。<br>釣り人が公開をためらう理由は、ほぼ「ポイントを知られたくない」ことだけです。そこで、場所は伏せたまま条件・釣り方・魚種・サイズだけを公開できる真ん中の選択肢を用意して、公開のハードルを下げます。<br>釣り場そのものも公開・非公開を選べます。公開する場合の位置は、緯度経度を小数第2位で切り捨てて、だいたい1km四方のマス単位で表示します。正確な位置は登録した本人にしか見せません。<br>【釣り場が非公開のときのルール】釣り場が非公開なら、そこにひもづく釣行を「全体公開」にしても、自動的に「釣り場だけ隠す」として扱います。つまり、釣行の公開範囲と釣り場の公開設定のうち、必ず「閉じているほう」を優先します。フィード・お知らせ・釣行詳細のどこでも、非公開の釣り場の名前と位置は出しません。<br>写真のExif（撮影日時と位置の情報）は、公開・非公開に関係なくアップロード時に消して保存します（FN-08）。 |
| FN-13 | 共有・公開 | 公開釣果の閲覧（釣果フィード） | 他のユーザーが公開した釣行を、新着順・釣り場別・魚種別に見られます。投稿者はニックネームだけを表示し、メールアドレスなど本人が特定できる情報は出しません。<br>「今どこで・どんな条件で・どんな釣り方で何が釣れているか」が見える状態をつくります。釣り場カルテには自分の実績と他人の公開実績を並べて表示します。<br>この画面はログインしていない人（ゲスト）でも見られるようにします。写真・魚種・サイズ・条件・釣り方・現地の情報・おおまかな位置まで見せます。登録する前に何も見えないと、ユーザーが増えないからです。ただし、正確な位置・条件検索・CSV出力・投稿・編集・釣行の詳細ページはログイン後だけにします。ゲストはメインフィールドを持たないので、見るたびに都道府県を選びます（FN-17）。<br>この機能は他のユーザーが増えるまでは効きにくいので、公開釣果が少ない間は画面を空にせず、自分の記録と釣り場の現地情報を表示して「最初の投稿者になる」導線を置きます。リリース時には開発者自身の過去釣行を数件登録・公開して、初日から空でない状態で始めます。 |
| FN-14 | 共有・公開 | 釣り場の現地インフラ情報 | 釣り場ごとに、現地で役立つ情報を記録・閲覧できます。<br>【選択式で持つ項目】駐車場（公式駐車場・路肩など・駐車不可・不明）、トイレの有無（あり・なし・不明）、最寄コンビニまでの距離（メートル）、注意区分（立入注意・私有地隣接・注意あり・なし）。<br>【自由入力のメモに書くもの】足場の良し悪し・柵の有無・危険な場所、夜間の照明、携帯の電波、自販機や釣具店の近さ、風向きに強い地形かどうか（北風に強いなど）。これらはどれがよく書かれるかを見てから、順次選択式の項目にしていきます。先に項目を増やしても空欄だらけになるためです。<br>【登録できない釣り場】釣り禁止・立入禁止の場所は登録できません。規約で禁止し、登録フォームにも注意書きを出します。釣りはできるけれど注意が必要な場合だけ、上の注意区分で表します。<br>【この機能を先に作る理由】釣果と違って、１人が１回登録すればその釣り場へ行く全ユーザーの役に立ちます。翌年以降も有効で、隠す理由もありません。だからユーザーが少ない時期でも成り立つ共有情報であり、Phase 1 の共有機能の一番手にします。<br>【入力してもらうタイミング】①釣り場登録時は知っている範囲だけの任意入力で、空欄でも登録できます。②釣行を登録した直後に、その釣り場でまだ空欄の項目を１〜２問だけ聞きます（行った直後が一番覚えていて、負担も小さいため）。③釣り場編集からいつでも直せます。<br>【編集権限】現地の情報は登録した本人だけでなく、全ユーザーが編集できます。みんなで更新し続けられる形にするためです。ただし最後に更新した人と更新日を画面に表示して、いつ時点の情報なのか分かるようにします。 |
| FN-15 | データ管理 | 釣り方（エサ／ルアー）の記録 | 釣れた魚１匹ごとに「エサかルアーか」を必ず選んでもらいます。仕掛けやヒットしたルアー、エサの種類などの細かい内容は、自由入力の備考欄に記録します。<br>潮・天候・時間帯とあわせて、「この条件ならこの釣り方」をあとで再現しやすくします。<br>備考に書かれた言葉は、将来よく使われるものを選択式にする余地を持たせます。 |
| FN-16 | 分析・可視化 | 釣行プランナー（日付から釣り場を提案）★主役 | まだどこへ行くか決めていないときに開く画面です。<br>日付を選ぶと、その日の潮（大潮・中潮など。計算で出します）と天気予報を表示します。そのうえで、自分のメインフィールド（都道府県）の釣り場を「過去に同じ条件で釣れたことがあるか」が多い順に並べます。県は画面の上で他の県や全国に切り替えられます（FN-17）。<br>釣り場ごとに、よく釣れた時間帯・釣り方（エサかルアーか）・魚種・これまでの最大サイズを表示します。そのとき「5回行って3回釣れた」のように、行った回数と釣れた回数の両方を出します。件数を隠さないので、その情報がどれくらい信頼できるかを自分で判断できます。<br>Phase 1 では、条件がぴったり同じ釣行だけを対象にします。１件もなければ「この条件で釣れた記録はまだありません」と表示します（条件を少しずつ緩めて探す機能は Phase 2 で追加します）。注意区分がついている釣り場には警告を出します（FN-14）。<br>FN-11 が「行く釣り場を決めたあと」の画面なのに対して、この画面は「どこへ行くかを決める」ためのものです。今の課題に一番まっすぐ答える主役の機能です。 |
| FN-17 | 検索・抽出 | メインフィールド（都道府県）設定とエリア絞り込み | 会員登録のときに、メインフィールド（よく行く都道府県）を必ず１つ選んでもらいます。あとでプロフィールから変えられます。釣り場を登録するときは、その釣り場がある都道府県を必ず選んでもらいます（位置から自動で県を判定することはしません）。<br>釣行プランナー・釣り場一覧・公開釣果フィード・ヒートマップは、初期状態でメインフィールドの県だけに絞って表示します。画面の上の選択ボックスで、他の県や全国に切り替えられます。<br>県境をまたぐ釣り場（湾の中など）は、この切り替えで対応します。隣の県を自動で含めることはしません（実装を単純に保つためです。必要になったときに追加できるようにしておきます）。<br>県で絞ると、車で行けない距離の釣り場が候補から外れます。また、全国にデータが薄く広がるより、１つの県に集まったほうが少ない件数でも実用的な密度になります。まず自分の県で成り立たせる設計にします。<br>県内に釣り場がない場合は画面を空にせず、「まだこの県には釣り場がありません／全国を見る／最初に登録する」の導線を出します。<br>ログインしていない人（ゲスト）はメインフィールドを持たないので、見るたびに都道府県を選んでもらいます。 |
| FN-18 | 共有・公開 | 県内新着のアプリ内通知 | 会員に向けて、自分のメインフィールド（都道府県）の新着をアプリの中でお知らせします。<br>【お知らせすること】①その県の釣り場に公開の釣行が登録されたとき。②その県に新しい釣り場が登録されたとき。投稿されるたびに１件とし、画面上のベルマークに未読件数を出して、お知らせ一覧（PG25）で確認します。<br>【お知らせしないこと】自分自身の投稿、非公開の釣行、非公開の釣り場。<br>【大事なポイント】お知らせは、画面とは別の経路でデータを外に出す仕組みです。だからお知らせの文章をつくるときに、もう一度公開範囲をチェックします。全体公開の釣行なら釣り場の名前を出してもよいですが、「釣り場だけ隠す」の釣行は「〇〇県で釣果が公開されました」のようにして、釣り場の名前を入れません。ここで名前を書いてしまうと、「釣り場だけ隠す」の設定が意味をなくしてしまいます。<br>【作り方】Laravel に標準であるお知らせの仕組み（notifications テーブル）を使い、テーブルは自分で設計しません。メールでの通知は、送信を後回しで処理する仕組み（キュー）の設定が必要になるので、今回は行いません。ユーザーはプロフィール（PG18）でお知らせのON／OFFを切り替えられます。<br>【この位置づけ】公開釣果を見せるだけでは、またアプリを開くきっかけがありません。そのための機能として Phase 2 の最初に作ります（Phase 1 のうちはお知らせする中身自体が少なく、機能が空回りするためです）。お知らせが多すぎて煩わしくなったときは、１日１回まとめて１件にする方式への変更を検討します。 |

### ■ 6. その他

※随時、機能についてはアップデートを予定しています。

※潮（大潮・中潮など）は釣行日時から計算で求め、天候は釣り場の位置と日時をもとに外部のAPI（天気データを提供してくれるサービス）から自動取得します。取得できないときは一覧から選んで手入力します。保存する値は、あとで集計できるよう決まった言葉だけにします。FN-16（釣行プランナー）は明日以降の条件を扱うので、過去の天気を返すAPIに加えて天気予報のAPIも使います（予報の値は表示するだけで、データベースには保存しません）。

※現地で困ること（自販機・釣具店・足場の良し悪し・柵の有無・夜間の照明・携帯の電波・風向きに強い地形かどうかなど）はこれからも洗い出して、釣り場情報の項目として順次追加していきます。

※リリース時に釣果フィードが空にならないよう、開発者自身の過去の釣行を覚えている範囲で数件登録して公開します（写真がないものは日時・釣り場・魚種・釣り方だけ、場所を伏せたい釣行は「釣り場だけ隠す」で登録します）。

※魚種は、同じ魚を別の名前で登録して集計が割れないよう、決まった一覧から選んでもらいます（アジ・サバ・イワシ・カマス・タチウオ・シーバス・ヒラメ・マゴチ・キス・マダイ・クロダイ・メジナ・メバル・カサゴ・アイナメ・カワハギ・ブリ・サワラ・アオリイカ・マダコの20種）。一覧にないものは「その他（自由入力）」で登録できます。淡水魚は今のところ選択肢に入れず、必要になったときに追加します。

※メインフィールド（都道府県）で絞り込む設計にします。県境をまたぐ釣り場（湾の中など）は、画面上の選択ボックスで他の県や全国に切り替えて対応します。隣の県を自動で含めることは、実装を単純に保つため行いません。

## ER図・リレーション

### ■ ER図・テーブル間リレーション定義書

テーブル同士のつながり方を表したシート。Model に hasMany / belongsTo を書くときに見る。

### 【エンティティ間リレーションシップ一覧】

| 主テーブル (親) | 関連テーブル (子) | リレーション種別 | 外部キー | Laravelリレーション定義 | 削除時動作 (Cascade) |
|---|---|---|---|---|---|
| users | spots | 1 対 多 (1:N) | spots.created_by -> users.id | User: hasMany(Spot::class, 'created_by')<br>Spot: belongsTo(User::class, 'created_by') | ON DELETE SET NULL（登録者が退会しても共有マスタとして釣り場は残す） |
| users | spots | 1 対 多 (1:N) | spots.updated_by -> users.id | User: hasMany(Spot::class, 'updated_by')<br>Spot: belongsTo(User::class, 'updated_by') → editor | ON DELETE SET NULL（最終更新者が退会しても現地情報は残す） |
| users | trips | 1 対 多 (1:N) | trips.user_id -> users.id | User: hasMany(Trip::class)<br>Trip: belongsTo(User::class) | ON DELETE CASCADE (親削除時に釣行も連動削除) |
| spots | trips | 1 対 多 (1:N) | trips.spot_id -> spots.id | Spot: hasMany(Trip::class)<br>Trip: belongsTo(Spot::class) | ON DELETE RESTRICT（他ユーザーの釣行が紐づく釣り場は削除できない） |
| trips | catches | 1 対 多 (1:N) | catches.trip_id -> trips.id | Trip: hasMany(Catch::class)<br>Catch: belongsTo(Trip::class) | ON DELETE CASCADE (釣行削除時に釣果も連動削除) |
| users | reports | 1 対 多 (1:N) | reports.reporter_id -> users.id | User: hasMany(Report::class, 'reporter_id')<br>Report: belongsTo(User::class, 'reporter_id') | ON DELETE CASCADE（報告者が退会したら報告も削除） |
| trips | reports | 1 対 多 (1:N) | reports.trip_id -> trips.id (NULL可) | Trip: hasMany(Report::class)<br>Report: belongsTo(Trip::class) | ON DELETE CASCADE（対象の釣行が消えたら報告も削除） |
| spots | reports | 1 対 多 (1:N) | reports.spot_id -> spots.id (NULL可) | Spot: hasMany(Report::class)<br>Report: belongsTo(Spot::class) | ON DELETE CASCADE（対象の釣り場が消えたら報告も削除） |
| users | password_reset_tokens | リレーションなし（独立テーブル） | password_reset_tokens.email（users.id への外部キーは持たない） | Laravel Breeze内部管理 | N/A (メールアドレスキー参照) |
